# Native Codex Kit · 1.1.0

Дата сверки документации: 27 сентября 2026 года.

Нативный комплект для цикла «контекст → решения → проверенный план → реализация →
ревью → доказательства». 17 skills, 13 custom agents, 14 специализированных
review-checklists, детерминированные проверки planning-артефактов и безопасная
локальная установка. Нет зависимости от OMX, собственного scheduler, MCP state
server, tmux, внешнего model runner или фонового сервиса.

Это переработка найденных feature-discovery v0.2.0, codex-agent-review,
review-kit v0.1.0 и пяти evidence-skills, плюс недостающие нативные workflows.
Это не побайтовая копия всех функций OMX и не снимок вашей локальной конфигурации.
Источники и границы совместимости: [SOURCES](docs/SOURCES.md).

## Быстрый старт

Нужны Python 3.11+ и актуальный локальный Codex с поддержкой standalone TOML agents.
Пакет не устанавливает и не обновляет зависимости. Сначала поместите распакованный
каталог в постоянное место: например, в отдельный репозиторий `~/Projects/native-codex-kit`.
Не устанавливайте симлинки из временного каталога, который затем удалите.

Из корня пакета:

```bash
python3 check.py                    # локальные проверки, без моделей и сети
python3 release.py                  # сверка SHA256SUMS со всем пакетом
python3 doctor.py --repo /path/to/project
python3 install.py                  # только просмотр предполагаемых изменений
python3 install.py --apply          # установка после проверки списка
```

`/path/to/project` замените реальным корнем проекта. `doctor.py` по умолчанию только
читает выбранные настройки; exit 2 означает проблему, например отсутствие `codex`
в PATH, невалидный конфиг, выключенных агентов или сломанный skill symlink.
Предупреждения о возможных дублях и OMX требуют осмотра, а не автоматического удаления.
Это ограниченная диагностика известных путей, не полный аудит всех plugin caches.

Установка создаёт ссылки `~/.agents/skills/<skill>` на папки этого пакета и копирует
TOML-файлы в `$CODEX_HOME/agents` — по умолчанию `~/.codex/agents`.
Сами skills не дублируются в каждом продуктовом репозитории.

Существующие несовпадающие файлы не перезаписываются автоматически. Для намеренной
замены после изучения коллизий:

```bash
python3 install.py --replace        # preview замен
python3 install.py --replace --apply
```

Перед изменениями создаются резервные копии. Путь к `manifest.json` выводится
установщиком. Текущие config.toml, auth, hooks, OMX и продуктовые файлы он не меняет.
`--replace` применяется только к одноимённым путям этого комплекта, не ко всему Codex.
Симлинки в промежуточных управляемых каталогах отклоняются: нестандартную раскладку
нужно осмысленно подключить вручную, а не разрешать произвольное следование ссылкам.

После первой установки список управляемых путей и исходных копий хранится в
`$CODEX_HOME/backups/native-codex-kit/active.json`. Перед обновлением или удалением
установщик сверяет эти записи с текущими файлами и прекращает работу при пользовательской
правке управляемого файла. Оба режима сначала показывают план:

```bash
python3 install.py --update
python3 install.py --update --apply
python3 install.py --remove
python3 install.py --remove --apply
```

`--update` обновляет копии агентов, перенаправляет ссылки skills при переезде
исходного каталога и убирает имена, исчезнувшие из новой версии. Новая коллизия с
чужим файлом требует явного `--update --replace`; прежний чужой файл сохраняется
для восстановления при `--remove`. Изменённый пользователем управляемый файл не
перезаписывается даже с `--replace`. `--remove` возвращает заменённые исходные
файлы; текст вне опционального блока `AGENTS.md` сохраняется. Установки прежней
версии без `active.json` можно откатить по их старому `manifest.json` через
`--restore`; автоматически приписывать им владение файлами нельзя.

Перезапустите Codex после установки; проверьте skills и реальный запуск ролей по
[smoke-сценариям](docs/SMOKE-TESTS.ru.md). Наличие файла само по себе не доказывает,
что именно установленная сборка его загрузила.

## Переход с уже установленного OMX

Сначала изучите [план миграции](migration/MIGRATION.ru.md). В
[migrate-local.prompt.md](migration/migrate-local.prompt.md) есть готовое задание
для локального Codex: инвентаризация, backups, адресное отключение только доказанно
OMX-owned инструкций/интеграций, установка и smoke-проверка. Доступа к вашему Mac в
ходе сборки не было; этот этап ещё не выполнялся.

Не удаляйте целиком `~/.codex`, `.omx`, `AGENTS.md` или все skills. Не запускайте два
конкурирующих orchestration contract одновременно. Исторические `.omx` планы могут
остаться как данные; активные OMX hooks/state/tool calls должны быть отключены
отдельно. Старые immutable packets не переписываются для нового расположения.

## Общие правила — отдельное осмысленное подключение

`AGENTS.native.md` содержит компактные общие договорённости, но не заменяет ваш
проектный `AGENTS.md`. Его установка опциональна:

```bash
python3 install.py --with-guidance
python3 install.py --with-guidance --apply
```

Файл добавляется управляемым блоком в глобальный `AGENTS.md`; существующий текст
сохраняется. При непустом глобальном `AGENTS.override.md` установщик откажется от
этого режима, поскольку override перекрывает обычный файл. Сначала разберите его
назначение. Добавление нового блока само по себе НЕ удаляет противоречащий контракт OMX.

Конфиг моделей, reasoning, sandbox, approvals и tools не перезаписывается.
В `config/agents.example.toml` находится только опциональный фрагмент с включёнными
агентами и лимитом трёх одновременно открытых дочерних потоков. В существующем
конфиге редактируйте уже имеющуюся таблицу `[agents]`, не добавляйте её второй раз.

## Какой skill запускать

| Задача | Skill | Результат |
| --- | --- | --- |
| Уточнить продуктовые решения | `$deep-interview` | Решения, assumptions, открытые вопросы |
| Небольшая задача с ясными требованиями | `$implementation-plan` | Короткий исполнимый план без тяжёлого процесса |
| Сложная фича/API→UI/несколько репозиториев | `$feature-discovery` | Проверенный frozen packet, traceability, prerequisites |
| Реализовать разрешённый объём | `$execute-plan` | Срезы, проверки, receipts, итоговый статус |
| Разделить независимую работу | `$parallel-work` | Ownership, native children, интеграционная проверка |
| Проверить изменения | `$code-review` | Независимые контексты, подтверждённые findings, coverage |
| Проверить security-риски | `$security-review` | Конкретные пути атаки, условия, mitigations |
| Проверить итог/ограниченно исправить | `$verify-work` | Фактические gate results, без бесконечного цикла |
| Найти причину сбоя | `$debug-by-evidence` | Воспроизведение, гипотезы, проверенная причина |
| Выбрать тестовое доказательство | `$testing-code-changes` | Проверки по риску, не test-per-method |
| Написать/проверить frontend-тесты | `$frontend-tests` | Vitest/RTL/browser по фактическому стеку проекта |
| Разобрать UI в реальном браузере | `$browser-debug` | Repro, DOM/console/network, явные ограничения |
| Обработать замечания | `$review-feedback` | Accept/reject/clarify с доказательствами |
| Проверить утверждения перед итогом | `$evidence-before-claims` | Claim → актуальное доказательство → границы |
| Оценить новый skill | `$skill-evaluation` | Сценарии с baseline; не путать syntax с качеством |
| Передать контекст | `$checkpoint` | Решения, ссылки, текущий scope и следующий шаг |
| Подготовить commit/MR-текст | `$git-message` | Заголовок/описание без Git/remote mutation |

Тривиальная правка не требует интервью, плана и команды агентов. Не нужно запускать
весь список для каждой задачи. `feature-discovery` — полноценный planning-only
процесс; не вкладывайте его внутрь `implementation-plan` как обязательный этап.

Все skills по умолчанию manual-only: в `agents/openai.yaml` задано
`policy.allow_implicit_invocation: false`. Вызов — `$имя-скилла` в сообщении Codex,
не shell-команда. Это ограничение автоматического выбора, а не гарантия удаления
любой metadata из контекста. `disable-model-invocation` для этого здесь не используется.
Загруженный skill может координировать разрешённую native delegation; отсутствие
реальных spawn-tools нельзя заменить текстовой имитацией агента.

## Практический рабочий цикл

Планирование:

```text
$feature-discovery
Подготовь план реализации фичи <описание> в текущем репозитории.
Сначала исследуй фактические контракты, существующий UI и тестовую инфраструктуру.
Используй native Codex agents; продуктовый код и зависимости не меняй.
Не больше трёх дочерних потоков одновременно.
Артефакты: .ai/tasks/<task-slug>/.
```

После получения плана — отдельное текущее разрешение на реализацию:

```text
$execute-plan
Реализуй только Slice 0–2 из .ai/tasks/<task-slug>/index.md.
Исходники backend, зависимости и lockfile не меняй. Коммиты и push не делай.
Проверь критерии именно этого объёма, выполни требуемое независимое ревью.
Частично проверенный TEST ID не помечай полностью GREEN.
```

Ревью по явно выбранной базе:

```text
$code-review
Проведи полный review текущего diff относительно <существующий ref>.
Ничего не исправляй. Зафиксируй snapshot, действительные агентные проходы,
проверенные findings и то, что не удалось проверить.
```

`code-review` без уточнения использует строгий полный протокол: пять discovery-lanes
и отдельного verifier, пакетами максимум по три одновременно. Для небольшой правки
укажите `quick`: сокращённый scope всё равно показывается явно. Ни отсутствие
дефектов, ни одобрение документа не означают разрешение на remote approval/merge.

## Долгая работа и native Goals

Goals — опциональная возможность Codex, не зависимость этих skills. По документации
`/goal` доступен начиная с CLI 0.128.0; это НЕ означает, что эта версия поддерживает
все нынешние настройки standalone agents. Установленную версию и доступность
конкретных возможностей нужно проверить в собственной сессии.

В Codex, одним сообщением с объёмом, методом и ограничениями:

```text
/goal Используя $execute-plan, реализуй только Slice 0–2 из .ai/tasks/<task-slug>/index.md. Завершение: все критерии разрешённого объёма, обязательные проверки и независимое ревью подтверждены. Не меняй зависимости, не делай commit/push. При блокере или исчерпании бюджета остановись с checkpoint, не расширяй объём.
```

Управление: `/goal`, `/goal pause`, `/goal resume`, `/goal clear`.
Goal принадлежит потоку Codex и ограничен состоянием, бюджетом и stop conditions.
Файл `status.md` не возобновляет Goal, не восстанавливает worker по старому ID и не
создаёт фоновый процесс. Без Goals skill работает в текущей сессии и оставляет handoff.

## Роли и передача контекста

`nc_scout` делает первичную карту; `nc_explorer` исследует конкретный сложный путь;
`nc_docs` проверяет первичные документы. `nc_planner` синтезирует план,
`nc_architect` проверяет границы, `nc_critic` оспаривает полноту и допущения.
`nc_implementer` и `nc_test_writer` пишут только назначенные файлы.
`nc_tests`, `nc_reviewer`, `nc_security`, `nc_browser`, `nc_verifier` проверяют
соответствующие поверхности и возвращают evidence координатору.

Префикс `nc_` избегает замены встроенных `worker`/`explorer` и старых ролей. Модели
и reasoning явно не задаются: действуют нативные spawn/default/parent settings.
Реальное имя модели нужно брать из runtime, а не угадывать по названию роли.
Разные экземпляры той же модели — не cross-model review.

Дочернему агенту передаются scope, snapshot, принятые решения, ссылки на источники,
owned files, договорённости по интерфейсам и проверкам. Общие artifacts меняет только
координатор. Дочерние агенты не создают внуков. Конкурирующие изменения одного файла,
lockfile, shared type или fixture сериализуются. Native children в общем worktree
не получают изоляцию лишь от того, что у них разные контексты.

У 11 исследовательских ролей стоит `sandbox_mode = "read-only"`; два пишущих агента
наследуют permissions родителя. Live overrides родительской сессии могут менять
эффективные разрешения дочерних агентов. Инструкция «не писать» не является
самостоятельной security boundary. При недоступности браузера/нужных permissions
результат ограничивается, а sandbox и инструменты не меняются автоматически.

## Что хранится в проекте

Только артефакты конкретной задачи, например:

```text
.ai/tasks/<task-slug>/
  index.md
  draft/                  # только пока идёт планирование
  revisions/
    r01/
      manifest.json
      packet/               # неизменяемая копия draft
  reviews/
  execution-handoff.md
  status.md
  receipts/
  ledger.json              # необязательно для длинной задачи
```

Детальная структура задаётся `skills/feature-discovery/references/artifacts.md`.
Создавайте frozen revisions штатными helpers, не вручную. `.ai` не является скрытым runtime Codex, permission-token
или аналогом Team mailbox. Коммитить ли task-артефакты — политика проекта;
установщик `.gitignore` проекта не меняет.

Для долгой задачи можно скопировать [пример ledger](templates/ledger.example.json)
в её каталог и записывать состояние срезов, ссылки на receipts и следующий шаг.
Это обычный временный файл задачи: он не запускает агента, не продлевает разрешение
и не восстанавливает Goal. Перед продолжением сверяйте его с текущими исходниками.

## Проверка и откат

```bash
python3 check.py --output .local-validation
python3 install.py --restore /actual/backup/manifest.json
python3 install.py --restore /actual/backup/manifest.json --apply
```

Откат проверяет подписи текущих установленных файлов и резервных копий.
Изменённые после установки пользовательские файлы он не перезаписывает.
Промежуточные пустые каталоги/backup manifest могут оставаться; это не очистка всего home.
При ошибке установки, обновления или восстановления предусмотрен откат уже
изменённых путей, если резервные копии остаются читаемыми.
При прерывании процесса/ошибке файловой системы изучите manifest и backup вручную;
это не транзакционная файловая система и не гарантия восстановления после power loss.

В поставку входят фактические логи [validation](validation/VALIDATION.json).
139 детерминированных тестов прошли в среде сборки: 95 planning guards + 44 проверки
пакета/установки. Live Codex, реальные модели, браузер и ваша машина здесь не
проверялись. [Smoke-сценарии](docs/SMOKE-TESTS.ru.md) помечены NOT_RUN, а не PASS.

Обновление: обновите этот постоянный каталог/репозиторий и выполните `--update`
сначала в preview. Ссылки skills ведут в исходный каталог, поэтому правка его
содержимого становится видна до запуска `--update`; не меняйте активный source
непроверенными пакетами. Скопированные agents и исчезнувшие имена сверяет установщик.
Для существующего plugin distribution используйте этот каталог `skills/`
в своём проверенном manifest и `--agents-only` для ролей; не включайте одновременно
plugin-копию и user-link одного skill. Этот архив сам не зарегистрирован в marketplace.

Для локальной сборки нового архива после проверки содержимого:

```bash
python3 check.py
python3 release.py --write
python3 release.py
python3 release.py --zip /path/outside/repo/native-codex-kit-v1.1.0.zip
```

`release.py` откажется упаковать изменённые или неучтённые файлы без новой сверки
`SHA256SUMS`; ZIP создаётся в фиксированном порядке и с фиксированными метаданными.
Публичная публикация требует отдельной проверки прав на материалы из
[списка источников](docs/SOURCES.md); этот локальный набор не заявляет лицензии
на все адаптированные входы.
