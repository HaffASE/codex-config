# Изменения относительно прежних наборов

## 1.1.0 — локальный жизненный цикл

Состав skills и agents остаётся нативным для Codex: без Team, hooks, daemon,
scheduler или собственного исполнения моделей. Установщик теперь хранит инвентарь
управляемых путей и резервных копий, показывает план `--update`/`--remove` и
останавливается при пользовательской правке управляемого файла. Обновление убирает
устаревшие имена; удаление восстанавливает заменённые исходные файлы. `doctor.py`
показывает состояние установки и расхождения с пакетом без записи на диск.

Добавлен необязательный `templates/ledger.example.json` для состояния долгой задачи.
Он не является recovery-механизмом Codex. `release.py` проверяет полный список
файлов по SHA256SUMS и собирает воспроизводимый ZIP за пределами исходного каталога.
Права на публичное распространение адаптированных исходников отдельно не заявлены.

## Runtime и совместимость

OMX control-plane заменён native Codex tools/threads. Вызовы question/state/team/ask
не подменяются похожими строками: их цели перераспределены между обычным диалогом,
нативной delegation, task-артефактами и опциональными Goals. Нет внешнего CLI worker.
Standalone agents используют name, description и developer_instructions.
Роли не меняют выбранную пользователем модель и не навязывают reasoning tier.

## Instruction budget

17 компактных skill entrypoints; детальные review-протоколы, profiles и templates
читаются по необходимости. 14 тематических reviewer-инструкций не превращены в
14 дополнительных автоматических глобальных skills. Все invocation policies
manual-only. Для тривиальных задач оставлен прямой путь без планировочного ритуала.

## Planning

Feature discovery изолирован от execution. Реальные user decisions сохраняются;
новые native capabilities не подделывают старые reviewer identities. Frozen packets,
SHA, per-file verdicts, full/delta reviews и prerequisites не упрощены до свободного
Markdown-резюме. Перед исполнением нужен текущий scoped authorization, но явный
запрос «реализуй этот план» не требует повторного формального согласования.

## Работа и проверка

Один владелец общей интеграции и task artifacts, явная собственность worker на файлы,
никакой уверенности в worktree isolation по числу контекстов. Свежее доказательство
после релевантных изменений. Missing tools и zero test discovery не считаются PASS.
Никаких fake cross-model verdicts. Repair/review budgets не сбрасываются вложенными
вызовами или переименованием задачи.

## Установка

Dry-run по умолчанию, backup перед записью, конфликт имён блокирует установку,
повторная установка без изменений, explicit replacement, защищённый restore.
Config/auth/hooks/OMX и продуктовые репозитории автоматически не меняются.
Global guidance подключается отдельно с сохранением существующего текста.
Для адресной миграции реальной машины приложен отдельный локальный prompt.

## Ограничения проверки

95 перенесённых planning tests и package/install tests выполнены локально.
Не запускались реальные Codex агенты, Goals, браузер и модели; поведенческие кейсы
в docs/runtime-evals.json помечены NOT_RUN. Нельзя интерпретировать количество
unit tests как вероятность соблюдения скилла моделью или доказательство превосходства.
