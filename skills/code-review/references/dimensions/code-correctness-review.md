# code-correctness-review

## Метод

Восстанови вход → преобразования → выход/побочные эффекты. Для diff сравни base и head. Проверь null/undefined/empty, неверные идентификаторы, порядок операций, ошибки и частичный успех. Проследи минимум одного реального caller изменённого public API и путь обработки ошибки. Соотнеси типы с runtime validation. Проверь тесты как evidence ожидаемого поведения, не как подтверждение прохождения. Найди конкретный вход и нарушаемый результат для каждого defect.

## Проверки против ложноположительных выводов

Нельзя заявлять bug только из сложности, названия или потенциального рефакторинга. Нет точного сценария — question/observation. Не создавай тесты и не исправляй код. Архитектурный стиль оценивают отдельные dimensions.

Верни кандидаты, evidence и gaps по общему protocol.md. Не делегируй и не исправляй код.
