# backend-architecture-review

## Метод

Установи фактическую модель проекта: explicit ADR, соглашения либо pragmatic framework layout. Для каждой затронутой границы определи владельца сценария, данных, транспортного контракта и инфраструктурного lifecycle. Сопоставь обещанный public API с реальным использованием. Проверь, не требует ли изменение одной фичи синхронной правки несвязанных сценариев. Предлагай минимальное перемещение ответственности вместо автоматического введения интерфейсов. Отделяй текущее нарушение от гипотетической будущей переиспользуемости.

## Проверки против ложноположительных выводов

Application service с TypeORM не является defect без explicit правила или реального impact. Facade из трёх delegation methods может быть сознательной границей. Наследование AuthEntity с persistence metadata может быть допустимым контрактом внутреннего модуля. Generic не означает поддержку двух registration одновременно. «Trade-offs: нет» не использовать без оценки ownership/import/API изменений.

Верни кандидаты, evidence и gaps по общему protocol.md. Не делегируй и не исправляй код.
