# Задание для локального Codex: перейти с OMX на Native Codex Kit

Запусти Codex из корня распакованного `native-codex-kit` и передай ему текст ниже.
Этот запрос разрешает только описанную локальную миграцию; он не разрешает менять
продуктовые исходники, публиковать данные, устанавливать пакеты или менять credentials.

---

Переведи моё окружение с OMX на нативный Codex, используя комплект в текущем каталоге.
Сначала прочитай README.ru.md, migration/MIGRATION.ru.md, install.py, doctor.py и
AGENTS.native.md. Найди действительные HOME и CODEX_HOME; не угадывай пути.

1. Проведи read-only инвентаризацию native Codex version/capabilities, user config,
   user AGENTS.md/AGENTS.override.md, native/legacy skill locations, custom agents,
   известных hooks/MCP/plugin registrations и относящихся к запуску shell wrappers.
   Если текущий Codex запущен под OMX, отдели фактические host-инструкции текущего
   процесса от конфигурации следующего запуска. Не пытайся игнорировать действующие
   host permissions. Не читай/не печатай auth.json, token values, cookies и ключи.
   Осматривай только связанные с миграцией файлы, без обхода всего домашнего каталога.
   Product repositories меняй только если я отдельно явно указал их для миграции.

2. Составь список обнаруженных активных OMX-зависимостей с точным файлом и причиной.
   Отличай runtime entry от исторической ссылки в plan/evidence. Проверь skills с
   одинаковым name: новый user-level skill не «сливается» со старым plugin skill.
   Укажи неизвестные registrations/capabilities, не объявляй их проверенными.

3. До записи сделай timestamped backup каждого изменяемого файла в отдельном
   безопасном каталоге. Сохрани paths и SHA. Для смешанного AGENTS.md выдели OMX-owned
   block и пользовательские правила; не удаляй целый файл. Не меняй model/provider,
   reasoning, sandbox/approval defaults, transport/proxy и непричастные MCP.

4. Адресно отключи только доказанно OMX-owned lifecycle hooks, state/MCP registrations,
   orchestration injection и конфликтующие skill registrations. Сохрани реальную
   структуру TOML/JSON; проверь её после изменения. При неоднозначном владении оставь
   конкретный entry нетронутым и отметь блокер, продолжая независимые безопасные шаги.
   Не удаляй .omx artifacts/state, .codex, .agents или все agents целиком. Не убивай
   чужие сессии/tmux/processes. Не запускай npm/brew/pnpm uninstall, installs или update.

5. Выполни python3 check.py. Затем python3 install.py в preview и изучи изменения.
   Разрешаю установку файлов этого комплекта и добавление AGENTS.native.md управляемым
   блоком; сохраняй прочие правила. При совпадении names сначала сравни файлы; только
   подтверждённую намеренную замену проводи с backup и --replace. Если непустой
   AGENTS.override.md перекрывает глобальный AGENTS.md, согласуй активный contract
   точечным редактированием, а не удалением override. Не создавай второй [agents].
   Проверь, что каталог-источник стоит в постоянном месте; симлинки не должны вести
   во временный каталог. Роли устанавливаются standalone TOML, не OMX prompts.

6. Выполни doctor.py. Подготовь новую прямую native Codex сессию без OMX wrapper.
   Не представляй переоткрытие сессии текстовым обещанием. Если текущий host не может
   безопасно проверить новый process, остановись после установки и дай точную
   команду/сообщение для ручной проверки в новой сессии. Не запускай отдельный codex
   exec как скрытый multi-agent worker или платный evaluation без моего разрешения.

7. В новой доступной сессии проверь фактическую загрузку manual skills и standalone
   ролей nc_scout и nc_reviewer: два реальных read-only вызова, разные instance IDs,
   без продуктовых правок. Разрешён именно этот небольшой capability smoke-test.
   Если запуск/аутентификация недоступны, зафиксируй NOT_RUN, не имитируй ответы.
   Goals проверяй только при наличии команды; не активируй цель с изменением кода.
   Полные поведенческие evals, browser и внешние модели в это разрешение не входят.

8. Верни миграционный отчёт: что и почему изменено, backups/diff, результаты команд,
   фактически проверенные capabilities, оставшиеся дубли/блокеры, ограничения и точный
   способ отката. Не называй установку полной миграцией до проверки нового active
   contract. Не делай commit/push/MR и не меняй исходники продуктов.

Если разрешения среды блокируют запись вне workspace, не обходи sandbox: подготовь
точечные изменения и команды, отделив выполненное от того, что требует моего запуска.
Не задавай повторно вопросы, ответы на которые доступны в прочитанных настройках.
Не принимай старую запись в артефакте за текущее разрешение на дополнительное действие.
